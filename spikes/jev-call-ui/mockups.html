Jev call: three directions

Mockups before code. Each direction puts the roster diagram and the Jev call on one screen: the call's question types, instructions, criteria, and the questions themselves. Click any piece or row and every direction follows the same player.

The players, slots, splits, analyst labels and rule-baseline labels are the real 2026 Wild Card roster bundle (dated 2026-09-27). The request text is what buildProfileRequest produces today. Jev's answers are made up for the mockup; no live call was made.

What a Jev call is

One request per player: a plain-text state, then a set of keyed questions. Each question has a type, instructions and criteria. All three directions have to show these four parts without hiding the evidence. 

POST /v1/systemone
{
  "model": "jev-latest",
  "state": "Player: Roman Anthony (mlbam-701350)
            Bats: L · Age: not available
            Eligible fielding positions: LF, RF
            Against LHP: .588 OPS over 83 PA …",
  "questions": {
    "profile": {
      "type": "choice",
      "instructions": "Which single profile label …",
      "criteria": { "Square": "…", "Star": "…", … 9 }
    },
    "evidence_sufficient": {
      "type": "noul",
      "instructions": "Do the supplied observations …",
      "criteria": { "true": "…", "false": "…" }
    }
  }
}
Questions
Keyed asks in one call. Today there are two: profile and evidence_sufficient. A future call could add more (for example a position-fit question) without touching the engine.
Type
choice returns one option plus a full probability distribution. noul returns one probability that the true criterion holds.
Instructions
The sentence the model answers. It forbids arithmetic and prose, so the answer can never become a run total.
Criteria
For a choice, one definition per shape with its recorded rule. For a noul, what true and false mean. The rubric version is part of the cache key.
DIRECTION A

Tag on the piece

The board stays the decision's one diagram. Selecting a piece hangs the Jev call on it like an inspection tag: the evidence it was given, each question with its type and instructions, and every criterion with Jev's probability. Analyst and rule labels sit beside Jev's as marks, so disagreement is visible without leaving the board.

Good for

  • Keeps D-50's one-board rule; the call is a detail of a piece, not a new page.
  • Reads player by player, which matches how a call is actually sent.
  • Criteria rows double as the explanation of the shape.

Costs

  • Roster-wide agreement is hard to see; you inspect one piece at a time.
  • The tag is tall. On a phone it drops below the board.
DIRECTION B

Call sheet

The call is the main object. Questions are a list you can add to; the selected one opens as a form with its type, instructions and criteria table, and the state template shows which fields come from which source and what is withheld. Below, the call is run across the roster: one row per player with analyst, rule and Jev side by side, and a small board that outlines every disagreement.

Good for

  • Makes the call itself editable and versionable, which is the "type-safe Jev" part of the project.
  • Roster-wide agreement and coverage are one glance.
  • Shows what is withheld from the prompt (analyst label, age), which keeps the comparison honest.

Costs

  • The board shrinks to a thumbnail; the shapes stop carrying the argument.
  • Feels like a tool screen, closer to Snapshots than to a decision.
DIRECTION C

Criteria lanes

The criteria become the diagram. Each of the nine profile criteria is a lane, and every piece sits in the lane its source chose, at true scale. Flip the source between Jev, the rule baseline and the analyst and the pieces move lanes. The noul question draws as texture: a piece Jev says had thin evidence is hatched.

Good for

  • Shows the criteria and the answers as one picture; the rubric is the axis.
  • The source toggle is the clearest way to see where Jev and the rules part ways.
  • Works as a new subpage under D-50 without displacing the board.

Costs

  • Gives up packing, so it says nothing about empty space or value off the field.
  • Instructions get one line; the full state lives in the side card.
